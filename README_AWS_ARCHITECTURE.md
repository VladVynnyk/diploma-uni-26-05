# AWS архітектура проєкту

## Що використовується зараз

У поточній реалізації AWS уже використовується для зберігання фото користувачів.

- Фото аватарів завантажуються в Amazon S3.
- Backend зберігає та оновлює посилання на файл у базі даних.
- Інші частини системи зараз працюють у звичайному application stack:
  frontend, backend, PostgreSQL, Redis і reverse proxy.

## Якою може бути цільова AWS-архітектура для дипломного проєкту

### Frontend

Можливі варіанти розміщення:

- Amazon S3 + CloudFront для статичного Next.js build.
- EC2 + Nginx, якщо потрібен SSR або власне середовище запуску.

### Backend

Backend API можна розмістити:

- на Amazon EC2;
- або в Amazon ECS/Fargate, якщо потрібен контейнерний підхід.

### База даних

Для PostgreSQL доцільно використовувати:

- Amazon RDS for PostgreSQL.

Це спрощує резервні копії, оновлення та моніторинг.

### Redis

Для кешування можна використовувати:

- Amazon ElastiCache for Redis;
- або Redis на окремому EC2, якщо потрібен дешевший навчальний варіант.

### Зберігання файлів

Для медіафайлів, зокрема фото користувачів:

- Amazon S3.

### Reverse proxy і вхідний трафік

Для розподілу трафіку можна використати:

- Nginx на EC2;
- або AWS Application Load Balancer.

### Секрети та доступи

Для production-середовища бажано використовувати:

- environment variables;
- IAM roles;
- AWS Secrets Manager або SSM Parameter Store.

## Узагальнена схема

1. Користувач відкриває frontend.
2. Frontend надсилає API-запити на backend.
3. Backend працює з PostgreSQL і Redis.
4. Фото та інші файли зберігаються в S3.
5. Вхідний трафік проходить через Nginx або ALB.

## Чому це підходить для диплома

Така схема показує реальний сучасний підхід до побудови web-системи:

- окремий frontend;
- окремий backend;
- керована база даних;
- кешування;
- файлове сховище;
- масштабований мережевий вхід.
