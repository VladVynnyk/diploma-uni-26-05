# Опис системи для дипломної роботи

## Призначення системи

Система є платформою для замовлення та керування консультаціями між клієнтами і консультантами.

Користувач може:

- знайти консультанта;
- переглянути його профіль, теги та відгуки;
- створити запит на консультацію;
- отримати або надати консультацію;
- залишити відгук після взаємодії.

## Ролі в системі

### Клієнт

Клієнт може:

- переглядати консультантів;
- створювати запити на консультацію;
- бачити власні консультації у dashboard;
- скасовувати свій запит, якщо це дозволено бізнес-логікою;
- залишати відгуки.

### Консультант

Консультант може:

- вести власний профіль;
- вказувати опис, вартість і теги;
- отримувати запити на консультації;
- змінювати статус своїх консультацій;
- переглядати відгуки про себе.

### Адміністратор

Адміністратор є звичайним користувачем з прапорцем `is_admin = true`.

Адміністратор може:

- переглядати всіх користувачів;
- змінювати admin-статус користувачів;
- переглядати всі консультації;
- змінювати статус будь-якої консультації;
- переглядати всі відгуки;
- переглядати всі теги;
- бачити системну статистику в dashboard.

## Чому використовується таблиця `order`

У поточній архітектурі окрема таблиця для consultation request не створюється.
Для цього використовується вже наявна таблиця `order`, яка логічно розширена до сутності запиту на консультацію.

Це дозволяє:

- не ламати поточну структуру проєкту;
- повторно використати вже наявні зв’язки між клієнтом і консультантом;
- мінімізувати ризик регресій;
- зберегти простоту для дипломної реалізації.

## Поля консультації

Сутність консультації зберігає:

- клієнта;
- консультанта;
- ціну;
- тему консультації;
- повідомлення клієнта;
- бажану дату та час;
- тривалість у хвилинах;
- статус;
- дату створення.

## Статуси консультації

Для керування життєвим циклом консультації використовуються такі статуси:

- `new`
- `confirmed`
- `in_progress`
- `completed`
- `cancelled`

### Значення статусів

- `new` — запит щойно створений.
- `confirmed` — консультант або адміністратор підтвердив запит.
- `in_progress` — консультація вже проходить.
- `completed` — консультація завершена.
- `cancelled` — консультацію скасовано.

## Робочий процес

1. Клієнт обирає консультанта.
2. Клієнт створює запит на консультацію.
3. Запит з’являється у dashboard консультанта.
4. Консультант підтверджує або веде консультацію через статуси.
5. Після завершення клієнт може залишити відгук.
6. Адміністратор контролює систему через розширений dashboard.

## Dashboard

У системі не створюється окрема сторінка `/admin`.
Замість цього використовується спільний dashboard.

- Звичайний користувач бачить свої персональні дані, відгуки та консультації.
- Адміністратор бачить додаткові розділи для системного керування.

## Де тут AWS

У поточній реалізації AWS уже використовується для зберігання фото в Amazon S3.

Для повної production-архітектури дипломного проєкту система може бути розгорнута з використанням:

- S3 і CloudFront для frontend;
- EC2 або ECS для backend;
- RDS for PostgreSQL для бази даних;
- ElastiCache або Redis на EC2 для кешування;
- S3 для медіафайлів;
- ALB або Nginx для маршрутизації трафіку.
